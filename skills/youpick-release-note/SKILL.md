# 新期发布说明（Claude 亲笔写）

**真源**：`E:\AI\orca-worktrees\09_YouPick\09_social-auto-upload\docs\closed-loop-decisions.md`
**触发**：老泡儿一句话「写这期发布说明」「这期文案」「发布说明衔接上期留言」

## 铁律（老泡儿 2026-11-14 拍板）

**这个环节由我（Claude）本人亲自写，不是代码随机拼模板。**
上期关联 + 互动环节不能少，但**句式不能定死、期期不重样**——老泡儿原话：
「每期互动都雷同就没意思了」「我是举例给你一个启发，不是让你定死了就得这么写」
「得需要你自由发挥」。

## 我写之前先看三样（不自嗨）

1. **上期被采纳的粉丝留言**——库里 `candidates` 表 `decision='采纳'` 且还没标「已满足」的：
   ```
   SELECT candidate_id, nickname, text FROM candidates
   WHERE decision='采纳' AND source_tag='粉丝' ORDER BY candidate_id;
   ```
2. **上期实际用过的发布说明**——看历史别撞车：
   ```
   SELECT * FROM candidates WHERE decision='已满足' ORDER BY candidate_id DESC;
   ```
3. **这期新视频内容**——老泡儿给的题材/11 部门回执的资产描述。

## 不可避免的硬骨架（缺一即废）

- **上期关联**：至少钩住一条真实的上期留言（署名或半署名，别把人 ID 写错）。
- **互动环节**：要有人味儿动作——招呼上期留言的几位、欠的账认了、下期点题征询、卖个关子。**每期换着来，别期期一个"评论区言语一声"。**
- **胡同串子口气**：得嘞/您嘞/嗬/甭急/局气/瓷实，京片子不换。
- **不编事实**：没拍的集不硬许、没发生的互动不硬说、上期留言原话不许瞎改。

## 我写的时候自由发挥（不许偷懒）

- **风格轮换**：有时唠家常式，有时认怂式，有时甩个包袱，有时正话反说——看这期内容和上期留言的气质搭不搭。
- **句式不重样**：上期用过"劳驾各位惦记"，这期就不再用的同款；上期用"您嘞"，这期换"得嘞"。
- **长短随心**：有时三五句短促，有时多扯两句，按内容来。
- **不套模板**：没有固定句式可套——每期都是新写。

## 我写完之后（落库待过目）

1. 写完贴给老泡儿过目（原话贴出来，不改动）。
2. 老泡儿点头后，落库存档 + 标「已满足」：
   ```python
   # 用哪条上期留言就把哪条标掉，防下期重复钩
   store.decide_candidates([candidate_id], "已满足", note="用于第N期发布说明")
   ```
3. 发布（须老泡儿单独点头，红线不改）。
