## 1. 产品定位

**卖服务不卖代码**：把自用的 orca 中枢大脑（01~99）模板化包装成产品对外售卖——核心交付是
「远程安装 + 售后 + 客服 + 远程控管」，持续收费；L1 内核能力中枢独享，09 只调用不持有。
样板间 = P2「微信视频号全自动 AI 交互号」（发布→读评→互动→候选→拍板→新集 全 AI 参与）。

## 2. 三档版本规划（销售切分）

| 版本 | 定位 | 核心能力 | 阉割点（引流/限客） |
|---|---|---|---|
| **体验版**（引流） | 让客户上手即见闭环、留钩子 | 单账号 · 单平台 · 只读 + 少量互动（限日额）· 基础候选整理 | 多账号/多平台封死；定制人设封死；远程托管封死；闭环第 4~6 步（拍板→派工→新集）只演示不通 |
| **标准版** | 主力成交 | 全闭环 · 单账号 · 可自托管 · 定制人设 · 候选→拍板 | 多账号矩阵封死；远程托管为选配；优先客服无 |
| **至尊版** | 大客/矩阵 | 多账号多平台 + 远程托管 + 定制人设 + 优先客服 + 数据看板 | 全开；含远程安装/维护/SLA |

## 4. 技术架构要点

- **多平台多账号库（M1 核心）**：`interaction_store.py` 从 `(export_id, 单账号)` 扩成 `(platform, account)` 复合主键；
  调度按账号分节奏、分人设、分内容，避免「几个号一个味儿」的关联风控。
- **模板组装引擎（打包引擎）**：从 01~99 插件库摘 L2 外核插件组合行业模板；验收「一句话 → 自动分析所需插件 → 集成打包成型」。
- **远程服务封装**：远程安装/维护/客服通道产品化、持续收费（L1 内核独享，09 调用不持有）。
- **人机协作不改**：草稿 → 老泡儿过审 → 发，前期永不开全自动群回。

## 6. 验收 KPI（立项即定，防货不对板）

- 每版本均能在新账号端到端演示闭环；
- 单号周互动量（点赞+回复）基线；候选采纳率（老泡儿拍板采纳 / 搜集）；
- 客户续费率（至尊/标准）；体验版→标准版转化率（引流达标线）。

## 7. 风险与红线

- **平台风控 / 限流**：号有历史限流记录（2025-12-23 一条视频被暂时限制传播），前期宁慢勿猛。
- **多账号关联风控**：同内容、同文案、同步节奏必被识别，按号分人设分节奏。
- **客户数据隔离**：评论/账号数据落 09 自管 L1 路径，不进公共库；出境（远程后台）走 L3 申请。
- **绝不去的线**：验证码绕过 / 设备指纹 / 批量养号 / 刷量——卖出去也不能让客户把号作死。
- **合伙边界**：对外发送（发布/回帖/点赞/删除/置顶）仍须老泡儿单独点头；部署/重启服务端/改库须明确批准。

## 8. 交付与计费（卖服务不卖代码的命门）
