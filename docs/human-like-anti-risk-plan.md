## 一、先说清楚边界（别把事儿办歪）

咱做的不是「对抗平台检测」，是**让 AI 代运营的节奏、文案、工作量都收敛到真人客服的水平**：
该慢就慢、该挑就挑、该请示就请示、该歇就歇。平台规则得守，账号有历史限流记录（2025-12-23 一条视频被暂时限制传播），
宁可少发、少回、慢养，也别一口气猛刷。凡是涉及「绕过验证码 / 改设备指纹 / 模拟多设备 / 批量养号」的路子，一概不碰。

## 二、五层闸门

| 层 | 管什么 | 单一真源 / 现状 |
|---|---|---|
| L1 节奏层 | 每一步之间的随机停顿、阅读时间、逐字输入、走神 | `nap()` / `human_read()` / `human_type()` ✅ 已落地 |
| L2 会话层 | 单次上线随机干 3~7 件就收工、活跃时段 9~22、单日 ≤200 条、防重复 id | `HumanSession` + `logs/human_session_state.json` ✅ 已落地 |
| L3 内容层 | 草稿去模板化、北京胡同串子口气、不编造事实、不带「测试/自动/验证/联调」字样 | `build_reply_draft()` + 人工过目 ✅ 半成品 |
| L4 选择层 | 不按点赞排序，按「剧情潜力 / 提问 / 具体」挑候选；spam 过滤；**自测样本打标剔除** | `pick_valuable()` ✅ 已落地；来源标签 ⏳ 待补 |
| L5 授权层 | `SEND_ENABLED` / `approved` / `dry_run` 三道闸；发布、回帖、点赞、置顶、删除逐类点头 | `human_reply()` + 各脚本 `--approved` ✅ 已落地 |

## 三、真人节奏的硬指标（已实现，照这个验收）

- **导航** 2.5~6s；**页面沉淀** 3~8s；**滚动** 1.2~3.5s；**点击** 0.8~2.5s；**发送前** 2~6s。
- **8% 走神**：随机再加 4~12s（喝口水、回个消息的工夫）。每次停多少秒都打日志 + 落 `logs/human_pace.log`，不黑箱。
- **先读再回**：按留言字数算阅读时间 `1.2 + min(字数,200)×0.09`，再乘 0.7~1.5 抖动。
- **逐字敲**：40~200ms/字，标点处偶尔犹豫；不整段粘贴。
- **两条回复之间** 35~120s；**两个会话之间** 3~10 分钟。
- **批量任务不是「一口气」**：2026-11-13 亲友批 6 赞 + 6 回复，按上面节奏实跑约 15 分钟以上，
  中途每条都可见、可拦，不是十秒刷完。

## 四、量与时段（保守取值）

- 单日回复上限 **200**（老泡儿口述，未经平台核实，先按它收着；正式跑建议再压到 30~50 条/号/天起步，观察两周再加）。
- 活跃时段 **9:00~22:00**，夜里不操作。
- 单次上线随机 **3~7 件**动作就收工；单账号单日总量、跨号不同文案，别几个号同一套话术齐刷。
- 新号 / 有限流记录的号：A 阶段先铺 **3~5 集引子**，只做「发片 + 少量高质量互动」，不满月不上批量。

## 五、文案与身份

- 人设：**北京胡同串子**，俏皮带损劲儿但底子热乎；起句随机（`HUTONG_OPENERS`），别每条都「嗬，您这话说的」。
- 一律 `needs_human_review=True`：AI 起草 → 人过一遍 → 发。引子期不开放全自动回帖。
- **不编事实**：没拍过的「下集」不硬许；没养过的「胖狗」不写；修过的文案要复查。
- 合规：不带「测试 / 自动发布 / 验证 / 联调」；AI 生成内容让平台自动打标，不掩饰。
- 不许自己回自己：比对 `username == auth_data.finderUsername`；主号自己的 L2 也剔掉。
- **来源标签（待补，P1）**：`亲友自测 / 引子埋钩子 / 自然流量` 三态必须进留言快照，
  否则第 4 步「按潜力挑剧情」会被自己埋的「玻璃栈道 / 海鸥 / 灯塔」带跑偏（老泡儿 2026-11-13 已点破这个坑）。

## 六、对外动作清单与验收

| 动作 | 接口 | 硬验收 | 状态 |
|---|---|---|---|
| 发布视频 | `sau tencent` | 真发一篇 + 后台可见 | ✅ 16:34 小猫 |
| 读留言 | `comment_list` | `errCode=0` + 字段 `commentContent/commentLikeCount/likeFlag` | ✅ 18:05 / 18:33 |
| 顶层回复 | `create_comment` | 发完**回读**命中 `levelTwoComment` | ✅ 18:14 |
| 2 级楼中楼 | `create_comment` + `rootCommentId=顶层` | 回读确认挂对层、不是自己回自己 | ✅ 18:40 批（详见 `reply_batch_0413.log`） |
| 点赞 | `like_comment(scene=1)` | `likeFlag` 由 0→1；**先判 `likeFlag` 防 UNLIKE** | ✅ 18:40 批 |
| 置顶 / 删除 / 拉黑 | `set_top_comment` / `del_comment` / `block_user` | 参数已定位，**未验、不主动碰** | ⏸ 冻结 |

通用规矩：默认 dry run → `--approved` 才真发 → 失败不重试、不盲发第二条 → 回读硬核验 → 落盘日志与响应样本。

## 七、监控与刹车

- 每次 `errCode != 0` 或会话过期（`300334`）→ **立刻停批**，先走 `skills/tencent-quick-login/SKILL.md` 恢复会话，再人工看一眼，不自动续跑。
- 出现「限制传播 / 评论不可见 / 验证码 / 频次提示」→ 当日停机，留痕报老泡儿，第二天再议。
- 三本账要齐：`logs/human_pace.log`（节奏）、`logs/human_session_state.json`（量）、`logs/reply_batch_*.log`（动作与核验）。
- 每次批量跑完出一张「动作 / 成功数 / 失败数 / 回读命中数」小表，贴进 `docs/closed-loop-decisions.md`。
